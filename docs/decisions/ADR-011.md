# ADR-011: 桌面端独立前端（脱离 Web 套壳）

- **状态**: Accepted（2026-10-07 修订：技术栈由 Svelte 5 改为 React + antd）
- **日期**: 2026-10-06
- **决策人**: ADui

---

## 背景

ADR-004/007 时代桌面壳（Tauri）直接复用 Web 的 React 构建产物
（AGENTS.md §17"桌面最大程度复用 Web UI"）。实践中暴露的问题：

1. **打包后云端连接断裂**：Web 请求是同源相对路径（`/api/v1/...`），
   devUrl 开发态经 Vite 代理可用；打包后 webview 加载内嵌资源，
   相对路径指向 Tauri 私有 origin，登录/会话/技能等云端功能不可达，
   且壳内没有"服务器地址"配置面；
2. **交互形态错配**：桌面是常驻多面板工具，Web 是浏览器页面流——
   信息密度、窗口布局、键盘交互诉求不同；
3. 用户方向决策（2026-10-06）：桌面端界面更现代化，**不套壳 Web 端**。
   按 AGENTS.md §77 用户当前要求优先于 §17 既有约定，本 ADR 记录替代方案。

## 决策

1. **新前端包 `apps/desktop-ui`**：React 19 + antd 6 + Tailwind v4 +
   TypeScript（2026-10-07 用户决策修订：初版用 Svelte 5，实测观感后改用
   React + antd 以对齐 Web 端组件体系与审美基准——参考 ZCode / Codex
   的桌面布局形态），Tauri Rust 壳与既有命令（runner_status /
   spawn_runner / runner_stop、通知、opener）保持不变；
   `tauri.conf.json` 的 frontendDist 切至 `../../desktop-ui/dist`
   （dev 端口 5176）。
2. **领域零复制**：`packages/`（contracts / agent / workflow / skill-sdk）
   照常共享；Web 的 `lib/` 请求层不共享——桌面 UI 的请求层以**绝对
   基址**为一等公民（服务器地址是本地设置项，P1 缺口在新 UI 内原生解决）。
3. **技术栈理由（修订后）**：React + antd 与 Web 端同一组件体系，
   深色主题 token 可复用，组件成熟度与布局能力（Layout / Menu）
   直接支撑类 ZCode / Codex 的侧栏 + 主区桌面形态；M1 逻辑层
   （lib/ 纯 TS + 测试）跨技术栈完整保留，视图层重写代价可控。
   代价：包体由 Svelte 版的 gzip ~18KB 增至 ~208KB（antd），对
   桌面安装包可接受。
4. **迁移路径（增量并行，不阻塞现有交付）**：
   - M1（本次）：骨架 + 服务器地址/登录 + Runner 控制 + 云 Runs 列表；
   - M2：本地 Runs（读 ADR-010 的 SQLite）、审批、终端；
   - M3：Workspace 文件/Git/编辑器、Chat、对比；
   - M4：移除 Tauri 对 web dist 的依赖，AGENTS §17 由本 ADR 替代。
     迁移期间 `apps/web` 不变（浏览器端继续可用），两套 UI 共享同一
     云端 API 与 Runner REST 契约。

## 影响

- Release 流水线三平台 job 的前端构建步骤切至
  `pnpm --filter @adui-forge/desktop-ui build`；
- `.svelte` 文件不在 oxfmt/oxlint 检查范围，桌面 UI 的类型/逻辑
  质量靠 TS（lib 层）+ vitest 逻辑测试保障；
- 桌面端 i18n、主题与 Web 端**不再共享**（各自演进）；
- 迁移完成前，桌面安装包的功能面以 M1-M2 里程碑为准（Web 套壳的
  全功能桌面版在 M4 后由新 UI 逐步补齐）。
