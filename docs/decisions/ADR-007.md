# ADR-007: Runner 以 Bun Compile Sidecar 随安装包分发

- **状态**: Accepted
- **日期**: 2026-09-13
- **决策人**: ADui

---

## 背景

v0.7.0 的桌面安装包**不含 Runner**——本地工作区/Agent 功能需要开发者手动
`node --import tsx/esm` 启动 `apps/runner`，打包用户完全不可用（ADR-005 留白）。
要让安装包开箱即用，Runner 必须以独立可执行文件随包分发，且不需要用户机器预装
Node.js。

## 决策

1. **分发形态**：Runner 用 **Bun `--compile`** 打成单文件可执行 sidecar：
   `bun build src/index.ts --compile --target <triple>`。产物内置运行时，
   用户机器零依赖。实测 86 MB（Windows x64，含 Fastify）、启动 < 1s、
   `/health` 即刻可用。
2. **多平台矩阵**：Windows x86_64（msvc）、Linux x86_64（gnu）、macOS arm64/x64。
   Bun 支持从任一宿主交叉编译全部 target——CI 在一个 job 内产出所有 sidecar。
3. **Tauri 集成**：`bundle.externalBin: ["binaries/forge-runner"]`——构建期 CLI
   按 target triple 找 `binaries/forge-runner-<triple>`，运行期安装在主程序旁
   （triple 后缀剥除）。`spawn_runner` 按 `FORGE_RUNNER_BIN` 覆盖 →
   `current_exe()/forge-runner` 顺序解析。
4. **运行时变更接受度**：Runner 从 Node/tsx 换为 Bun 运行时。实测兼容面
   （fastify、node:fs、node:child_process、node:crypto、zod）全部可用；vite-plus
   测试仍跑在 Node（Bun 仅用于生产运行与编译）。风险点若出现，Node SEA 为备选。
5. **开发模式**：`tauri dev` 下可用 `FORGE_RUNNER_BIN` 指向
   `bun run --watch` 进程不可行（spawn 需可执行文件）——统一用 compile 产物，
   `scripts/build-runner.mjs` 一键重建当前平台 sidecar。

## 被否决的备选方案

| 方案                                | 否决原因                                                          |
| ----------------------------------- | ----------------------------------------------------------------- |
| 要求用户预装 Node + tsx             | 安装包开箱即用是硬前提                                            |
| Node SEA（单可执行）                | 需先把 TS bundle 成 CJS；Fastify 5 的 ESM/动态加载在 SEA 下风险高 |
| Rust 重写 Runner（并入 Tauri 进程） | 违反 ADR-005 §1（Rust 只做 Native Bridge）与单一实现原则          |
| Docker 容器跑 Runner                | 桌面用户安装门槛高（同 ADR-006 §5）                               |

## 后果

- Release 流水线新增 Bun 安装 + sidecar 编译步骤（分钟级）；产物体积 +86 MB/平台。
- `spawn_runner` 不再依赖用户机器的 Node——原 `node --import tsx` 路径移除。
- Bun 运行时升级与 Node LTS 安全公告脱钩，需在依赖巡检中关注 Bun 版本。
