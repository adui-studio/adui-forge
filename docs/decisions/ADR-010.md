# ADR-010: Local Runner 运行持久化（SQLite）

- **状态**: Accepted
- **日期**: 2026-10-06
- **决策人**: ADui

---

## 背景

Local Runner（ADR-005）的 Runs 此前是**纯内存态**：桌面应用重启后本地
Run 历史（任务、输出、事件流）全部丢失；移动端/Web 复查历史只能依赖
云端 Runs。用户侧的合理预期是"本地执行过的任务在本地留痕"。

约束：

- Runner 以 `bun build --compile` 单文件 sidecar 分发（ADR-007）——
  不能要求用户安装或配置任何数据库；
- 开发态经 Node/tsx 运行（终端支持，ADR-007 备注），该环境没有
  `bun:sqlite`；
- 云端 API 继续使用 PostgreSQL（多用户并发场景，不随之变更）。

## 决策

1. **存储**：Bun 内置 `bun:sqlite`（零依赖、单文件），整行 JSON payload
   存 `runner_runs(id, created_at, payload)` 表——事件流形状由
   `contracts` 演进，不做关系列拆分（本地单用户，无查询维度需求）。
2. **契约**：`RunnerRunPersistence`（upsert / loadAll / close）注入
   `RunnerRunService`；服务在 queued / running / 每个事件 / 终态四个
   时机整行落库。工作集仍是内存 Map，持久化是写透镜像（write-through），
   不引入异步写队列。
3. **重启语义**：恢复历史时，**非终态 Run 显式收敛为 failed**（error:
   "runner restarted before completion"）——执行进程已随上次退出消失，
   不允许永久悬挂的 running 让客户端无限轮询。
4. **路径与降级**：DB 路径由 Desktop Shell 注入
   `FORGE_RUNNER_DB`（app_data_dir/runner-runs.db，不污染用户工作区）；
   未注入、或运行在非 Bun 环境（bun:sqlite 不可用）时**显式回退内存**
   并打警告——与 ADR-005/006 的显式降级惯例一致。
5. **Node/tsx 开发态**：保持内存（`createSqliteRunPersistence` 返回
   null），不在 Node 侧引入 `node:sqlite` 的版本/flag 兼容负担。

## 影响

- 桌面端本地 Run 历史跨重启保留；SSE 订阅者不持久化（重启后无订阅者
  属预期，客户端轮询 getRun 即可取到收敛后的终态）；
- `bun:sqlite` 为同步 API，事件高频时逐事件落库有写放大——本地单用户
  规模下可接受；若未来出现性能问题，再评估批量写（需新 ADR）；
- Desktop 壳新增 `FORGE_RUNNER_DB` 注入（app_data_dir），失败时
  `unwrap_or_default` 交由 Runner 端显式回退。
