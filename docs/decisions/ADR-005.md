# ADR-005: Local Runner 进程模型与 Tauri Capability 清单

- **状态**: Accepted
- **日期**: 2026-09-12
- **决策人**: ADui

---

## 背景

ADR-004 阶段 3 要求 Desktop 的本地工作区由 Local Runner 接管，且对前端暴露与云端
**同一套 REST 形状**。需要固定 Runner 的进程模型、与 Tauri Shell 的职责边界、以及
安全 capability 清单（AGENTS.md §19/§20/§31）。

## 决策

1. **进程模型**：Runner 是 Tauri Shell 拉起的**独立本地进程**（`apps/runner`，Fastify +
   Node），仅监听 `127.0.0.1:<随机端口>`。Tauri 负责启动/停止进程与读取端口（§19：
   Process Lifecycle 归 Rust），Runner 自身不持有任何 Tauri API。
2. **REST 同形**：Runner 实现 `/api/v1/workspace/*`、`/health` 与后续的 Runs 子集，
   响应结构与云端 API 完全一致；文件操作复用 `@adui-forge/tool-sdk` 的
   `resolveInWorkspace` 边界与 `workspace-files` 纯函数（**单一边界、单一实现**）。
3. **Token 握手**：Tauri 启动 Runner 时通过环境变量注入一次性随机 token；Runner 校验
   `Authorization: Bearer <token>`，防止本机其他进程未授权访问。token 不落盘。
4. **Tauri capability 清单（最小化，§20 Least Privilege）**：
   - `runner:spawn` —— 以指定 workspace root 与随机 token 拉起 Runner 子进程；
   - `runner:stop` —— 终止子进程；
   - `runner:port` —— 读取子进程端口（进程间管道，非全局可写）。
   - **不授予**：任意 fs 读写、任意 shell、全局窗口句柄。
5. **框架**：Runner 采用 Fastify（技术栈 §4 既有），Lean 启动（无 Prisma/Redis/BullMQ），
   目标冷启动 < 1s，内存 < 80 MB。
6. **降级**：workspace root 未配置时 Runner 显式拒绝启动；端口占用时换端口重试（上限 5 次）。

## 被否决的备选方案

| 方案                                      | 否决原因                                                     |
| ----------------------------------------- | ------------------------------------------------------------ |
| Tauri Rust 直接实现文件/Agent 服务        | §19 禁止把业务写进 Rust；双语言维护成本                      |
| Runner 作为 Tauri 内嵌线程/sidecar 之外库 | 进程隔离崩溃互不影响；sidecar 二进制分发复杂度留给后续评估   |
| Runner 监听 0.0.0.0 或固定端口            | 本机其他设备/进程可未授权访问；固定端口易冲突                |
| 复用云端 API 进程跑在本地                 | 携带 Prisma/Redis 依赖，启动重；本地模式不需要持久化基础设施 |

## 后果

- 阶段 3 交付 Runner 骨架：health + workspace 同形端点 + token 校验 + inject 测试；
- Tauri 侧的 spawn/stop 落地属于 Desktop Shell 迭代（Rust 侧代码另行提交）；
- 前端 Desktop 通过 Tauri API 获取 Runner 地址后，把 `/api/v1/workspace` 请求指向
  Runner（PlatformAdapter 分发，云端/本地对页面透明）。
