# ADR-009: MCP Server 配置保持环境变量来源（不做运行时 CRUD）

- **状态**: Accepted
- **日期**: 2026-10-05
- **决策人**: ADui

---

## 背景

MCP 服务当前仅经 `FORGE_MCP_SERVERS` 环境变量配置（JSON 数组：name / command /
args? / env?），Agent 构建上下文在启动时逐个 stdio 连接并把桥接工具汇入工具池。
管理页（MCP）只能观测状态与按需重连测试。

一度考虑过"DB 化的 MCP 动态配置"（CRUD + 热重连）作为功能候选，本 ADR 记录
否决理由，避免后续把它误判为能力缺口。

## 决策

**MCP Server 的注册保持在环境变量来源，不提供运行时 CRUD。** 理由：

1. **注册 MCP Server = 授予任意进程执行权**。`command` 由平台以子进程方式
   启动；把注册入口从"运维控制的环境变量"放宽为"任意已认证用户可写的
   数据库配置"，等于把进程执行权从 operator-only 开放为 user-scoped——
   在多用户云端是权限模型的实质倒退（AGENTS.md §38 Command Injection、
   §44 MCP 最小权限）。
2. **MCP 内容本身即不可信输入**（AGENTS.md §44）：工具描述可携带注入载荷。
   连接面必须保持小而可审计；动态增删会让"当前平台信任了哪些外部服务"
   难以静态回答。
3. **收益有限**：目标场景（团队自托管、Server 侧配置）里服务清单变化频率
   极低，重启生效不构成实际负担。

## 影响

- `parseMcpServers` 与 `buildAgentBuildContext` 的启动时装配语义不变；
- MCP 管理页继续定位为**只读观测 + 连通性测试**；
- 若未来引入多租户或需要动态接入，必须先立新的 ADR 解决"谁可以注册、
  注册后的审计与审批"问题，而不是在本决策上做增量。
