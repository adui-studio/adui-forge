# ADR-001: 采用 Vite+ + pnpm Monorepo 工具链

- **状态**: Accepted
- **日期**: 2026-08-29
- **决策人**: ADui

---

## 背景

ADui Forge 是一个包含 Web / Desktop / Mobile / API / Worker / Runner / Docs 的多端项目，
需要统一的 Monorepo 工程方案，覆盖构建、Lint、格式化、测试与任务编排。

## 决策

1. 采用 **pnpm workspace** 管理依赖与 workspace（`apps/*`、`packages/*`、`tools/*`）。
2. 采用 **Vite+** 作为 JS/TS 统一工具链：
   - `vp dev / vp check / vp test / vp build / vp run`
   - 内置 Oxlint（Lint）、Oxfmt（格式化）、Vitest（测试）、任务缓存与 staged hooks。
3. TypeScript 6+（catalog 锁定），全仓库 strict 模式，ESM。
4. 依赖版本通过 `pnpm-workspace.yaml` 的 catalog 统一管理，默认 Latest Stable。

## 被否决的备选方案

| 方案                   | 否决原因                                  |
| ---------------------- | ----------------------------------------- |
| Turborepo / Nx / Lerna | Vite+ 已内置任务编排与缓存，无需额外引入  |
| ESLint + Prettier      | Oxlint / Oxfmt 已覆盖且更快，避免双套配置 |
| npm / yarn / bun       | 团队统一 pnpm，避免锁文件不一致           |

## 影响

- 所有 JS/TS 任务统一走 `vp` 命令；未经必要性验证不引入额外构建工具。
- git hooks 由 Vite+ 管理（`.vite-hooks/`，pre-commit 执行 `vp staged`）。
- 后续新增 Rust（cargo）与 Flutter（flutter pub）工具链时沿用各生态标准命令，不混入 Vite+。
