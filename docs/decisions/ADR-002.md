# ADR-002: 文档系统采用 Rspress 替代 VitePress

- **状态**: Accepted
- **日期**: 2026-08-29
- **决策人**: ADui

---

## 背景

原始需求（REQUIREMENTS.md 第 65 节）指定文档站使用 VitePress。
项目初始化时重新评估文档工具选型，需要与 Vite+ / Rsbuild 生态保持一致的工具链。

## 决策

文档站（`apps/docs`，MVP 阶段搭建）采用 **Rspress**：

- Rust 实现的构建核心，冷启动与热更新速度显著优于 Node 生态方案。
- 与 Vite+ / Rspack 生态工具链一致，构建心智统一。
- 支持 MDX、全文搜索、多语言、自定义主题，满足文档站需求。
- 组件生态基于 React，与仓库主技术栈一致。

仓库级规划文档（`docs/` 目录）保持纯 Markdown，不依赖文档站工具。

## 被否决的备选方案

| 方案              | 否决原因                                            |
| ----------------- | --------------------------------------------------- |
| VitePress         | 原方案；Vue 生态主题体系与本项目 React 技术栈不一致 |
| Docusaurus        | 构建较重，React 生态但配置面大                      |
| Starlight (Astro) | 引入 Astro 运行时，工具链不统一                     |

## 影响

- REQUIREMENTS.md、AGENTS.md 中的 VitePress 引用全部更新为 Rspress。
- MVP 清单中的 "VitePress Docs" 对应项改为 "Rspress Docs"。
- `apps/docs` 搭建时使用 `@rspress/core`（Latest Stable），输出目录纳入 `.gitignore`。
