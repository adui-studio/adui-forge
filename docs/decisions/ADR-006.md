# ADR-006: 本地 Runner 的 Sandbox 与审批模型

- **状态**: Accepted
- **日期**: 2026-09-13
- **决策人**: ADui

---

## 背景

本地 Runner（ADR-005）的 Agent 目前只有文件工具（边界内读写）。Shell/Git 工具需要
Sandbox：Docker 对桌面用户过重，HostSandbox 无隔离边界（AGENTS.md §42 要求显式信任）。
同时，shell_exec / git 写入是 approval 级工具——云端有人工审批闭环
（REQUIREMENTS §48），本地模式必须有等价机制，否则本地 Agent 等于绕过审批。

## 决策

1. **Sandbox 选型**：本地模式复用 **HostSandbox**（tool-sdk 既有实现），但仅在
   **Trusted Local Mode** 显式开启时装配 shell_exec / git 工具——与云端 API 的
   `FORGE_TRUSTED_LOCAL_MODE` 语义完全一致（AGENTS.md §42）。Docker 桌面方案与
   OS 级沙箱（Job Object / sandbox-exec）留作后续 ADR，接口不变、工具层零改动。
2. **信任开关的归属**：信任状态属于**用户决策**，不由 Runner 环境变量静默决定——
   Desktop 前端提供显式开关（默认关闭），开启时弹确认对话框说明风险；开关经
   Tauri 传给 Runner 启动参数（重建进程生效），Runner 日志打印警告。
3. **审批闭环**：Runner 内置轻量审批服务（与云端 ApprovalService 同语义、同
   事件形状）：
   - approval 级工具触发 → Pending 创建 → `approval.required` 事件经既有 SSE 推送；
   - 决策经 `POST /api/v1/approvals/:id/decision`（token 保护）resolve，Loop 继续；
   - 前端在 Agent 面板/Runs 视图渲染待审批卡（批准/拒绝）。
4. **默认拒绝**：Trusted Local Mode 未开启时，approval 级工具不装配——本地 Agent
   能力上限就是文件读写，与 v0.6.x 行为兼容。
5. **不做的事**：本地模式不引入 Docker 依赖、不做 OS 级沙箱、不让 Agent 自行开启
   信任模式（§50：Agent 不得绕过审批）。

## 被否决的备选方案

| 方案                                      | 否决原因                                                |
| ----------------------------------------- | ------------------------------------------------------- |
| 默认启用 HostSandbox（无信任门槛）        | 违反 §42：无隔离边界的进程执行必须显式信任              |
| 本地模式免审批（"用户在场即审批"）        | 违反 §50；Agent 连续执行时用户未必逐条看到命令          |
| Docker Desktop 作为本地默认 Sandbox       | 桌面用户安装门槛高；Docker 不可用时能力静默降级不可接受 |
| Runner 内嵌 Node 权限模型（--permission） | 实验特性、覆盖面不足；不能替代进程级边界                |

## 后果

- 本地 Agent 在用户显式信任后获得与云端 Agent 同级的 Shell/Git 能力，且审批闭环
  语义一致（同一事件名、同一 REST 形状）；
- Desktop 前端需新增信任开关与审批卡 UI（下一提交）；
- 未来引入 OS 级沙箱时仅替换 Sandbox 实现，工具与审批层零改动。
