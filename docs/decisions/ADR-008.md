# ADR-008: Windows Job Object 沙箱（本地 Shell 隔离的落地）

- **状态**: Accepted
- **日期**: 2026-09-14
- **决策人**: ADui

---

## 背景

ADR-006 让本地 Agent 在 Trusted Local Mode 下获得 Shell/Git 工具，但隔离手段是
**HostSandbox（无隔离）**——进程直接跑在用户机器上：无进程树限制、无内存上限、
命令崩溃可能留下孤儿进程。ADR-006 留白"OS 级沙箱后续 ADR"，本文件即该决策。

目标：在**不引入 Docker**（桌面用户门槛，ADR-006 §5 已否决）的前提下，给本地
Shell 执行提供操作系统级的最小隔离与清理保证。

## 决策

1. **机制**：Windows 使用 **Job Object**（`CreateJobObject` +
   `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` + 内存上限），把命令子进程放入 Job，
   沙箱对象销毁/超时/abort 时整棵进程树强制终止。POSIX 使用
   **detached + 进程组**（`process.kill(-pid)`）达到同等树杀语义。
2. **FFI**：经 **koffi**（纯 npm 依赖，无 node-gyp 编译）调用
   kernel32 `CreateJobObject` / `SetInformationJobObject` /
   `AssignProcessToJobObject` / `TerminateJobObject`。不写 Rust，不进 Tauri。
3. **实现位置**：`packages/tool-sdk` 新增 `JobObjectSandbox`（仅 Windows 生效；
   POSIX 下行为等同进程组树杀）。接口不变——`Sandbox` 协议的一个实现，
   工具层零改动（ADR-001 以来一直预留的扩展点）。
4. **选择逻辑**：Runner 在 Windows + Trusted Local Mode 下自动选用
   `JobObjectSandbox`；koffi 加载失败时**显式降级** HostSandbox 并打印警告
   （能力下降不静默）。
5. **限制边界（诚实声明）**：Job Object 提供**进程树生命周期与内存上限**，
   不提供文件系统/网络/注册表隔离——那些仍由三层文件边界 + 审批 +
   Workspace 根约束。它是"Host 无隔离"与"Docker 完全隔离"之间的中间档。

## 被否决的备选方案

| 方案                           | 否决原因                                                      |
| ------------------------------ | ------------------------------------------------------------- |
| Windows Sandbox / WSL          | 用户需启用可选功能，镜像 GB 级，启动秒级——桌面门槛过高        |
| Rust sidecar 承载 Job Object   | 违反 ADR-005 §1（Rust 只做 Native Bridge）与单一实现原则      |
| 继续用 HostSandbox（仅靠审批） | 审批拦截的是"是否执行"，拦不住"执行后失控"——命令本身可能 fork |
| chromium/zygote 式预 fork 池   | 复杂度与收益不成比例，MVP 不需要                              |

## 后果

- Windows 本地 Agent 的 Shell 执行获得：整树终止（超时/abort/会话结束不留孤儿）、
  Job 级内存上限（默认 2 GiB，可配）、进程数上限（默认 512）；
- POSIX 本地获得：进程组树杀（等价现状但有明确实现）；
- koffi 成为 tool-sdk 的可选依赖（Windows-only 引入，加载失败有显式降级路径）。
