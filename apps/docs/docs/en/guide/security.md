# Security Model

ADui Forge lets agents change real code — the security boundary is the first
design constraint.

## Sandbox First

Every process execution by an agent goes through the Sandbox abstraction,
never directly onto the host:

| Implementation | Isolation                                                                         | Condition                                       |
| -------------- | --------------------------------------------------------------------------------- | ----------------------------------------------- |
| Docker         | container: no network by default, memory/CPU/process limits, workspace-only mount | default (`FORGE_SANDBOX=docker`)                |
| Host           | none                                                                              | only with explicit `FORGE_TRUSTED_LOCAL_MODE=1` |

Mounting the root directory, user HOME, SSH keys or docker.sock is forbidden.

## Workspace Boundary

Every file-tool path input passes three layers of defense:

1. `../` traversal is rejected before real-path resolution;
2. symlink / junction escapes are re-checked against the realpath;
3. missing paths fail with a generic error — no host filesystem leakage.

Single-file writes are capped at 1 MiB and binary extensions are rejected via
the text API.

## Approval (Human-in-the-Loop)

The following require human approval by default; agents cannot bypass them:

- `shell_exec` (arbitrary shell commands)
- `git_add` / `git_commit` / `git_push`
- git push has extra hardening: `remote` / `branch` arguments cannot carry git
  options (blocks `--upload-pack`-style injection) and force push is rejected.

Flow: the loop suspends on an approval-level tool → `approval.required` event →
the user decides on the Web / Mobile approval view → the run continues or ends.
The Local Runner implements the same semantics (ADR-006), gated behind
Trusted Local Mode with an explicit consent toggle in the desktop UI.

## Auth & Secrets

- Passwords hashed with Argon2id; access tokens are HS256 JWTs (24h).
  `FORGE_AUTH_REQUIRED=1` enables global Bearer validation (off by default to
  keep local mode first).
- Model API keys can be referenced via `apiKeyEnv` (an environment-variable
  name) so keys never enter config files or logs.
- Secrets never reach source code / logs / commits; `.env` is gitignored, only
  `.env.example` is committed.
- MCP server content is untrusted input: bridged tools default to `approval`
  permission and inputs are JSON-Schema validated.
- The Local Runner listens on 127.0.0.1 only, with a per-session token
  generated by Tauri and never persisted to disk.
