# Plan — 先规划后动手

在 ADui Forge 仓库中执行任何开发任务（新功能、Bug 修复、重构）时，
实现代码之前必须先完成本 Skill 的三个阶段（对应 AGENTS.md Step 1–3）。

## 阶段 1 — 理解需求

先读 [AGENTS.md](../../../AGENTS.md) 与 [docs/REQUIREMENTS.md](../../../docs/REQUIREMENTS.md)，
确认以下要素，缺一项就先向用户澄清：

```text
目标
输入
输出
边界
影响范围
验收标准
```

## 阶段 2 — 阅读现有实现

禁止看到需求立即写代码。动手前先勘察：

```text
目标模块 README / package.json / pubspec.yaml / Cargo.toml
相关类型、相关配置、相关测试
代码搜索 + Symbol Search + git log
```

结论：复用什么、扩展什么、绝不动什么。

## 阶段 3 — 制定最小方案

输出一份简短计划，包含：

1. **方案**：改哪些文件、新增什么接口，每条附一句理由。
2. **最小化检查**：是否满足——最少修改文件 / 最少新增依赖 / 最少改变公共接口 / 保持现有结构与风格。
3. **验证方式**：计划执行的命令（`vp check` / `vp test` / `vp build`）与验收标准。

## 停下来确认的时机

出现以下任一情况时，先向用户确认再继续：

- 需求有歧义，或边界、验收标准不明确。
- 方案需要新增依赖、改变公共接口、或触碰 AGENTS.md §71 列出的重大架构变更
  （此时先写 ADR 到 `docs/decisions/`）。
- 发现用户有未提交修改，任务可能与其冲突（禁止覆盖、回滚、顺手重构）。

## 约束

- 计划里没有的任务不顺手做；实现阶段严格按计划执行。
- 方案确定后如发现与预期不符，回到阶段 2 重新勘察，不要边写边猜 API。
